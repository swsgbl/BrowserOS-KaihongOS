# 验收测试清单（BrowserOS-KaihongOS / P51-P56）

> 每项勾选前需要保存测试命令、原始日志、设备/SDK/BrowserOS commits、截图或数据对比。未运行就写 NOT RUN，不允许用“代码看起来正确”代替 PASS。

## A. 基线和构建
- [ ] 记录 deep HEAD、upstream HEAD、工具链版本、设备型号、KaihongOS build、API14/API23。
- [ ] `python tools/static_checks.py` 全通过；保存原始输出。
- [ ] HAP 构建、资源重打包、签名、安装、冷启动全部通过；保存 HAP SHA256。
- [ ] 当前分支 README/DEVPLAN/CHANGELOG/ARCHITECTURE 阶段号及 MCP 工具数一致。
- [ ] 两套基线区分 BrowserOS neo 与 BrowserOS main。

## B. MCP 协议与工具
- [ ] HTTP `/mcp`：无效 token 为 401；正确 token initialize 成功。
- [ ] WebSocket 握手：无 token/错 token 被拒绝；正确 token 可建立连接。
- [ ] legacy `2024-11-05` 与 current upstream `2026-07-28` 的协议协商正确。
- [ ] 官方 MCP SDK 完成 initialize → tools/list → tools/call；session header/handle 可继续使用。
- [ ] 17 项 tool 名称/required fields/可选字段与 upstream contract 自动比对。
- [ ] `tabs` list/active/new/close/activate 全通过。
- [ ] `tab_groups` create/list/join/leave/ungroup/cleanup（或明确声明不支持）全通过。
- [ ] `windows` 对每个受支持动作有效；不支持动作不会假成功。
- [ ] `navigate`、`snapshot`、`act`、`read`、`grep`、`diff`、`wait`、`screenshot`、`evaluate`、`run` 全通过标准 fixture。
- [ ] `act` 使用 snapshot 返回的稳定 ref；页面更新后 stale ref 返回明确错误。
- [ ] `download` start/status/cancel/list 端到端通过，包含 API14/API23 差异。
- [ ] `upload` 与 `pdf` 要么真实可用通过 E2E，要么不作为可用工具暴露并准确标记 capability。
- [ ] 限流、输出脱敏、请求尺寸、超时和错误码回归通过。

## C. Harness one-click setup
- [ ] Claude Code / Codex / Cursor / OpenCode / Antigravity / VS Code / Zed 的检测器有安装/未安装/权限不足/损坏配置测试。
- [ ] Connect 前备份目标 harness 原配置。
- [ ] Connect 后真实 config 中出现单一 BrowserOS entry；不是写进 App 沙盒就算成功。
- [ ] 重启 harness 后真实 `initialize` 与 `tools/list` 成功才标记 Connected。
- [ ] 重复 Connect 不生成重复 entry；Disconnect 仅移除本产品 entry。
- [ ] 写配置失败时恢复原文件，其他 MCP 服务器配置不变化。
- [ ] 同设备 localhost 与 host `hdc fport` 两种拓扑分别可实测连接。
- [ ] 所有 UI/clipboard/docs/test 的 URL/path/port/transport 一致。

## D. Session、并发、所有权
- [ ] 客户端 A 与 B 分别 initialize，各自拿到不同 session ID。
- [ ] A/B 同时 create tab、navigate、snapshot、act、screenshot；没有跨 session 作用。
- [ ] A 关闭自己的 tab，不影响 B；过期 tab/session 被拒绝。
- [ ] 应用重启、harness 重启、连接中断后的 session 恢复状态符合策略。
- [ ] Stop 只取消目标 session，并停止后续工具调用。
- [ ] 2 个与 5 个并发 agent 的截图 URL/内容均与正确 tab 对应。

## E. 登录态/密码库/安全
- [ ] Chrome direct-import 可用性有平台证据；不支持时 UI 明确给出文件导入路径。
- [ ] Netscape Cookie JSON / supported format 导入可预览域、数量、expiry 与错误。
- [ ] 登录状态在目标站点实际生效，重启仍按策略持续。
- [ ] localStorage-only fixture 有明确支持/不支持结果，不显示假成功。
- [ ] Bitwarden JSON import 有重复项和坏 JSON 测试；导出默认不泄漏明文。
- [ ] 停止、清理、删除凭据后，Preferences/Asset Store/缓存/备份中的旧数据已按策略清除。
- [ ] password/OTP/API-key canary 输入后，Preferences、Session JSON、logs、screenshots/replay、exports 不含可恢复敏感值。
- [ ] LLM API Key 仍由 Asset Store 安全存储；config.json 继续脱敏。
- [ ] loopback only、CSPRNG token、token 轮换、rate limit、安全敏感动作确认回归通过。

## F. Audit / Replay
- [ ] 内部 Agent 与外部 MCP client 的工具调用都进入统一 Audit ledger。
- [ ] Audit 列表支持 agent/status/site/date 搜索过滤；Live/Done/Failed 状态准确。
- [ ] 每个 tool event 带时间、tab/session、状态、错误、脱敏 input/output。
- [ ] 每个被录制的动作能关联对应的 screenshot/URL/tab。
- [ ] 同一 session 多 tab 可分别查看 timeline；不会串时间线。
- [ ] 若有 rrweb-like replay：可以 scrub DOM/scroll/click/动态内容；若只支持截图回放则 UI 明确说 screenshot timeline。
- [ ] 模拟磁盘满/进程 kill/JSON 损坏/录制 gaps 后，文件可恢复或会话标记 incomplete。
- [ ] 保留期策略删除会清除索引、截图和 replay 文件，无 orphan files。

## G. Profile / Tab groups / Browser behavior
- [ ] Profile / private / isolated context 的 Cookie、localStorage、History、session ownership 有隔离测试。
- [ ] tab_groups 可以按上游 schema 分组、解组、任务后保留/清理。
- [ ] 页面刷新/导航后旧元素 ref 被识别为 stale，不会点击错元素。
- [ ] 常见站点导航、重定向、popup/target=_blank、dialog、滚动、input、iframe、download 和权限流程已覆盖。
- [ ] 键盘焦点、Ctrl+L/R/T/W、屏幕缩放、中文/英文、深/浅主题通过设备验收。

- [ ] 所有 provider adapter 有独立连接、stream、tool call、错误和限流测试。
