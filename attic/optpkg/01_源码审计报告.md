## 二、结论先行

**深开鸿版已经从早期占位原型发展成可运行的 ArkWeb 浏览器与 AI 自动化应用；不能再使用此前“WebView 占位、MCP 全桩代码”的旧结论。**当前代码已经包含真实 WebView、标签/历史/书签、AgentEngine 15 步工具循环、SSE 流式、HTTP/WS MCP、17 个 MCP 工具名称、定时任务、基本 session 记录与回放 UI、密码库/Bitwarden JSON 导入、双语设置和多阶段设备证据。

但“12 屏界面已对齐”不等于与当前上游主线完整 1:1。当前最重要的差距不是再画页面，而是：

1. **外部 AI harness 的真正一键安装仍未实现**：`ConnectionManager.checkToolInstalled()` 直接 `return false`；`writeMCPConfig()` 只写 App 沙盒下 `connections/<tool>_mcp.json`，并未修改 Claude/Codex/Cursor 等程序真正读取的配置。MCP board 的主要可见动作是生成并复制 JSON。仓库中的 41/41 互操作测试只能证明所列客户端可以调用 MCP，不能证明配置被自动安装。
2. **MCP 名称 17/17 不代表语义 17/17**：`upload`、`pdf` 明确 unsupported；`windows` 只有 `list`；`tab_groups` 仅最小 `list/ungroup`；`act.ref` 用 CSS selector，而上游 `snapshot → act` 依赖稳定元素引用。协议版本仍写死 `2024-11-05`，而上游已显式支持 `2026-07-28` 与旧版本协商。
3. **外部 MCP session 隔离没有跟上上游**：`initialize` 会返回一个 Session ID/header，但后续 tool call 的 dispatch identity 是 `mcp_http`/`mcp_ws`，没有看到用 session handle 维护独立 browser session、tab ownership、profile target 与 epoch 防竞态的完整链路。并发 harness 下这是关键正确性风险。
4. **Chrome 登录态一键迁移仍缺失**：`detectChromeDataPath()` 返回 `null`，`readChromeCookies()` 和 `readChromeLocalStorage()` 返回空值；已有 cookie JSON 导入和 Bitwarden 密码库导入不是 Chrome profile 一键导入。
5. **回放不是上游 rrweb 式的真实页面回放**：深开鸿以固定间隔截图 + 操作日志构建播放器；上游 Neo 当前使用 rrweb/rrweb-player 与服务端 recording/replay store，能够沿时间轴复现 DOM/页面变化。并且 MCP 外部工具调用尚未看到统一接入 `SessionManager.addOperationLog` 的证据。
6. **密码库和审计记录有高优先级安全问题**：CredentialStore 的主存储路径把凭据数组 `JSON.stringify(all)` 写进 Preferences；Asset Store 是额外镜像而非主读取来源；导出 JSON 明确 `encrypted:false`。内部 Agent 还把工具参数前 60 字符写进 OperationLog，敏感字段可能泄漏。
7. **BrowserOS 主产品的能力不在 Neo 12 屏里**：若目标确实是整个上游仓库，还必须处理 Chromium/扩展/MV2 adblocking、20+ 内置工具、Cowork 本地文件工作流、多 Provider/OAuth、40+ 应用集成等另一套范围。ArkWeb 无 Chrome 扩展宿主属于平台限制，不能用 UI 替代后声称运行时兼容。
8. **项目台账已经明显落后源码**：README 仍写 MCP 10 工具、P1-P40；CHANGELOG 最新 P40；DEVPLAN 对新阶段的台账停在 P43 附近，但当前主分支已有 P49/P50 相关代码/提交。文档过期会让“缺失/已完成/待开发”三种状态混淆。

## 三、当前完成度怎么理解

这里不硬编一个百分比：UI 屏数、工具名称数和完整行为不是同一分母。更可信的结论是：

| 子系统 | 当前判断 | 解释 |
|---|---|---|
| 原生浏览器壳和一般网页浏览 | **基本完成 / ArkWeb 平台等价** | WebView 已真实挂载；标签、导航、历史、书签、主题、下载 UI 已有代码；不是 Chromium 内核复刻。 |
| UI 12 屏 | **历史快照覆盖高；当前主线视觉/交互需要重基准** | 有很多真实截图和 E2E 证据，但未见当前 upstream 每屏的自动视觉差异门禁。 |
| 内置 Agent | **基础链路完成，产品能力部分对齐** | 有 15 步循环、SSE、tool calls、stop 状态；内置工具约 9 个，provider 以 OpenAI-compatible 为主。 |
| MCP 工具面 | **名称覆盖高、协议/行为覆盖中等** | 名称可达 17 项且有互操作证据，但 upload/pdf/windows/tab_groups/session target 等有明确限制。 |
| MCP Harness 一键连接 | **未完成** | 目前主要是 endpoint + 复制 JSON；自动检测和修改宿主配置被桩代码阻断。 |
| 登录态/凭据 | **部分完成且需安全整改** | 手动 cookie 与 Bitwarden 路径有代码，但 Chrome profile 导入 stub；密码库应用层存储/导出安全不足。 |
| Audit / Replay | **基础版完成，非 rrweb 等价** | 定时截图与工具日志有基础结构；外部 MCP 审计、真实 DOM 回放和完整 audit 查询需补齐。 |
| 交付质量 | **有手工设备证据，但 release gate 不完整** | CI 主要是静态检查；本次没有独立构建 HAP 或重跑物理设备 E2E；正式签名仍待。 |

## 四、最高优先级的缺口（必须先处理）

| 优先级 | 缺口 | 为什么先做 | 建议里程碑 |
|---|---|---|---|
| P0 | MCP session/agent/tab ownership 与并发隔离 | 多个外部 harness 同时执行时可能串 tab、错截图或跨 session 操作；直接影响正确性和安全。 | P51 |
| P0 | 密码库 Preferences 明文 JSON、导出 encrypted:false | 凭据在 app 层没有可靠加密真值源，且导出包含明文密码。 | P51 |
| P0 | OperationLog 可能持久化 `type/fill` 的敏感参数 | 可能把密码、OTP、私有文本进入录制数据。 | P51 |
| P0 | “一键连接”检测/安装是桩代码 | 功能入口给用户造成连接成功的假象，核心 Neo 价值之一未交付。 | P52 |
| P1 | MCP protocol 版本过旧、Streamable HTTP 行为不齐 | 新 client 协议协商/会话语义不能保证兼容。 | P52 |
| P1 | upload/pdf/windows/tab_groups 语义缺失 | tools/list 名称覆盖不能保证客户端真实完成任务。 | P52-P53 |
| P1 | Chrome 登录态导入缺失 | Neo 最重要差异化能力之一是使用真实登录态做任务。 | P53 |
| P1 | rrweb 等价回放与外部 MCP 审计断链 | 透明性/可审计性是 Neo 核心功能，不可只展示截图幻灯片。 | P54 |
| P1 | Profile targeting 与 tab group isolation | 上游已经向 profile/session targeting 演进，深开鸿还以每标签/transport 级管理为主。 | P55 |
| P1 | CI 构建/设备 E2E/当前 upstream visual diff | 无法让后续 AI 开发在可靠回归门禁内持续推进。 | P56 |

## 五、功能差距矩阵说明

完整矩阵见 [`02_差距矩阵_详细核对项.csv`](02_差距矩阵_详细核对项.csv)，共 **99 项**，包括目标范围、当前判定、优先级、源码证据、建议动作及验收标准。状态分类不把“UI 有入口”当成功：

- **已实现（有代码/证据）**：当前可以在源码或仓库证据中找到实现，不等于本次重新实测通过。
- **部分实现**：有基础路径，但与上游当前语义、生命周期、数据模型或错误处理仍不同。
- **缺失/桩代码**：函数明确空实现、直接返回空/false、或工具 handler 明确 unsupported。
- **平台限制**：ArkWeb/系统能力与 Chromium 不同，应明确作为替代方案或不支持项，不可静默宣称 1:1。
- **待实机验证**：代码接线存在，但台账记录了设备/VM 行为未能端到端确认。
- **有意差异**：例如零遥测比上游更隐私，不应为了复制而无必要加入遥测。

## 六、建议开发路线（P51-P56）

### P51：先修安全和 session 正确性（阻断后续功能扩张）
1. `McpSessionStore`：initialize 创建 session；每次 call 必须携带/校验 session handle；记录 client、tab claims、profile target、创建时间、最后活动时间、TTL。
2. `BrowserTargetResolver`：所有 tabs/snapshot/act/read/screenshot/stop 都必须按 session + tabId + generation 定位，移除依赖全局 active tab 的隐式操作。
3. `AuditRedactor`：对密码字段、OTP、API key、`type/fill` 参数、敏感结果和截图先脱敏再写入 SessionRecord；新增 canary 测试。
4. 凭据加密迁移：Preferences 只保存非敏感索引/密文；Asset Store/系统 KeyStore 为主秘密存储。迁移必须幂等且清除旧明文；明文导出默认关闭。
5. 两个独立 harness 并行、跨 tab 操作、停止/恢复、旧 session 与 stale ref 的并发 E2E。

### P52：MCP 协议和一键连接闭环
1. 协议适配层支持 `2026-07-28` 与 legacy negotiation；补 server/discover、Streamable HTTP session lifecycle/notifications 的兼容测试。
2. 将 `ConnectionManager` 与 UI JSON 统一到唯一 endpoint/provider；删除 `/sse` 与 `/mcp` 双重来源。
3. 实现真实 harness detect/config adapter：Claude Code、Codex、Cursor、OpenCode、Antigravity、VS Code、Zed；配置备份、原子合并、幂等、回滚和 health-check。
4. UI 状态改为 Not installed / Detected / Configured / Awaiting restart / Connected / Error；真实握手成功前不能显示 Connected。
5. 按部署拓扑给本机使用与 hdc port-forward 使用两种准确配置。

### P53：登录态导入和浏览器能力闭环
1. 明确 KaihongOS 的 profile 文件读取权限边界；不能直接读取 Chrome profile 时，提供安全的 Netscape Cookie / JSON / Bitwarden import wizard。
2. import preview、域名列表、Cookie attributes、过期时间、失败原因、清理和重启持续性。
3. upload / pdf 能力：可实现就接系统文件选择和 PDF 导出；不可实现则 capability-filtering 并移除误导性的可调用工具。
4. 多 profile/隐身 storage isolation 的真实行为测试；不能把 `storagePartition` 字段存在当作隔离已实现。

### P54：真正的 audit / replay
1. MCP dispatch、内部 Agent、页面录制共用事件总线，所有外部 tool calls 统一进入 audit ledger。
2. 研究 ArkWeb 是否允许可靠注入 DOM mutation recorder；如可行实现 rrweb-like event stream/播放器；如不可行，正式定义降级方案并标记“截图回放”而非“视频/真实页面回放”。
3. Audit 列表支持 search/filter agent/status/site/date，详情支持每 tab timeline、args/result、错误状态和敏感脱敏。
4. recording manifest、gap detection、磁盘满、清理、原子写、进程重启恢复测试。

### P55：Profile、Tab groups、与上游行为等价
1. 新增 profile target model 与 session-to-target ownership；在 API14/23 逐项测试存储隔离。
2. 实现 tab_groups 真正的 create/join/leave/ungroup/cleanup。
3. 将上游 snapshot 输出 ref 与 act 输入 ref 统一到稳定节点引用；更新 wait/read/evaluate 的 stale reference 错误。
4. 对 BrowserOS neo 当前 UI 重新截图对齐，维护变更追踪，不只宣称“12 屏已完成”。

### P56：产品边界、测试门禁与正式发布
1. 设立 build runner：静态检查、ArkTS build、HAP 打包、API14/API23 smoke、截图对比、MCP conformance。
2. 建立 BrowserOS neo 与 BrowserOS main 两份 matrix；主产品-only 的 Cowork、扩展、20+ agent tools、多 Provider/OAuth、应用集成单独估算。
3. 更新 README/DEVPLAN/CHANGELOG/ARCHITECTURE/SECURITY，统一阶段号、工具数和连接方式。
4. 正式签名/升级迁移/回滚/供应链/仓库临时产物治理。

## 七、明确不能用来宣称“1:1”的证据

- 12 屏 UI 图片数量相同 ≠ 当前主线上视觉/交互一致。
- MCP `tools/list` 名称为 17/17 ≠ 工具行为、schema、错误与协议版本一致。
- 41/41 harness 兼容测试 ≠ harness 自动安装成功、并发 session 隔离或真实任务完整成功。
- 有录制按钮/截图播放器 ≠ rrweb 页面状态真实回放。
- 有密码库页面/Asset Store 镜像 ≠ 密码活动存储已加密。
- 有“连接”按钮/生成 JSON ≠ 配置已写入外部 AI 程序且完成握手。
- 在 VMware/模拟器跑过 ≠ 对真实 KaihongOS PC/平板全量适配。
