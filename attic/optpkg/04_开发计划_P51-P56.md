## 推荐执行顺序
1. **先 P51**：不做 session isolation 与 redaction，不建议继续开放更多自动化工具。
2. **再 P52**：连接 MCP 是 Neo 的核心入口。先修 protocol + installation semantics，再做用户增长/新 UI。
3. **P53/P54 可部分并行**，但共享 session ownership 和 redaction API，建议先完成 P51 的接口设计。
4. **P55 追行为等价**，用上游工具 contract 驱动实现，而不是仅靠页面截图。
5. **P56 发布门禁**贯穿每个阶段，最终固化所有差异与平台限制。

## 上游差异同步规则
- 每周抓取上游 main 最近提交和 docs/tool registry 变化。
- 对每个新增功能分为：Must match（Neo 核心）、Platform substitute（有明确替代）、Platform blocked（标记不可做）、BrowserOS-main-only（单列路线）、Intentional difference（如零遥测）。
- 7 天内给出状态与 owner；未确认的差异不能被记作“已经 1:1”。

## 发布停止条件
若以下任一存在，不应宣称“1:1 复刻完成”：真实 harness 配置未验证、外部 session 未隔离、密码/OTP 可能被持久化、upload/pdf 工具仍假暴露、录制不能审计外部 MCP 行为、无当前上游视觉与协议门禁。
